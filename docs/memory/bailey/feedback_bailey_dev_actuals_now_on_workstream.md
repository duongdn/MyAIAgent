On 2026-08-16, DatNC bulk-entered all then-current cumulative actual hours from the Paturevision Google Sheet ("Est vs Charged") into Workstream project `speedventory` (id `cmqyvio51000vqo0xhocbx5c9`) as single-day task-log rows (e.g. "[Prestashop] Grazing Software Desktop" = 99:00+99:00+25:57 = 223.95h, matching the Sheet exactly). Since then, TuanNT and others log hours **task-by-task, day-by-day directly in Workstream** — but the Sheet's actual-hours column is NOT being kept in sync.

**Why:** User flagged (2026-08-25, Vietnamese: "Hiện task đã đẩy lên Workstream ko phải task log nha") that `me:bailey-task-monitor` was reporting stale Sheet numbers. Verified via `/review/week` API: "[Console] Use Average Purchase Price When Adding Stock Manually" showed 0.0h/Not Started in the Sheet but had 5:35 (5.58h) actually logged in Workstream since 8/20 — already +365% over its 1.2h est+buffer, completely unflagged by the Sheet-based script.

**How to apply:**
- `scripts/bailey-task-monitor.py` (Sheet-based) is now only reliable for tasks with NO Workstream activity since 2026-08-16. For any task, before reporting 0h/Not Started or an overbudget number, cross-check live Workstream: `node scripts/workstream-fetch-project-week.js {date} speedventory` for member weekly totals, or hit `{api_base}/review/week?projectId=cmqyvio51000vqo0xhocbx5c9&date={date}` directly for per-task-name rows (the summary script strips task names — need raw fetch, see [[reference_bailey_monitor_skill_file]]).
- Actual per-task total = 2026-08-16 migration baseline (visible in that day's WS rows) + sum of all WS task-log rows with matching task name from 8/16 onward. The Sheet's "actual" column is stale for any task touched after 8/16.
- **FIXED 2026-08-25:** `scripts/bailey-task-monitor.py` now calls `scripts/workstream-fetch-speedventory-task-actuals.js` and uses that actual/charged instead of Sheet columns K/L whenever a match exists. Sheet metadata (status, payment, dev, type, estimate, link) still comes from the Sheet. Falls back to Sheet hours + "⚠️ stale Sheet, no WS match" tag when no match found. Overbudget check now also runs in "Other Active Tasks", not just "Has Bug" — closes [[feedback_overbudget_check_missing_from_other_active]].
- **CORRECTED same day (2nd pass):** first fix joined WS rows to Sheet rows by exact free-text task name — WRONG. Different WS task-log rows can carry the SAME display text but a DIFFERENT tag (e.g. TuanNT logged 5:00 on 2026-08-24 with text "Use Average Purchase Price When Adding Stock Manually" but `tags[0].tagId = "101"`, which per the Sheet's column C ("Task ID WS") is actually `[Console] Advanced Split Order` — a typo/copy-paste in the free-text field, not the real task). User caught this by eyeballing WS directly ("bên WS chỉ có 35m mà anh") when the script reported 5.58h for that task. **Correct join key is `row.tags[0].tagId` (uppercased) = Sheet column C, NOT `row.task` (free text) = Sheet column A.** The fetch script now aggregates by tagId and records `taskTexts` seen under each tag for diagnostics. Untagged WS rows (meetings, admin, "Testing tasks", etc.) have no billable task ID and are skipped. Re-verify: Use Average Purchase Price actual dropped 5.58h→0.58h (now within budget), Advanced Split Order actual rose 0h→5h, Grazing Software Desktop rose 223.95h→245.95h (name-matching had missed same-tag sub-bug-ticket rows with different free text).
